# Project Changelog - v1.2.3 (Auth Fixes & Component Snippets)

## Milestone: Working Admin Authentication

1. **Build and routing fixes**
   - `LoginPage.jsx` imported its UI components from a wrong relative path, which broke `vite build`. It now uses the `@/components/ui/...` alias.
   - Successful login now redirects to `/` (previously `/admin`, which has no route).

2. **Backend JWT enforcement**
   - `auth.middleware.js` is now applied in `src/index.js` to `/api/articles` (including publish/schedule), `/api/ai`, `/api/automation` and `/api/categories`.
   - `/api/auth`, `/api/public` and `/blog` stay open, so the Astro public site is unaffected.
   - Socket.IO connections are still unauthenticated (events only broadcast generation status).

3. **Frontend API client**
   - `api/client.js` attaches `Authorization: Bearer <adminToken>` to every request.
   - On a 401 (expired or invalid token) it clears the stored session and redirects to `/login`.
   - Added `api.login()`; `LoginPage.jsx` now uses the shared client.
   - `errorMessage()` also reads `message` from API error responses.

## Milestone: "New component" on the Components page

1. **Paste-in form**
   - `/dev/components` has a **New component** button that opens a form: name, HTML and optional CSS.
   - Saving writes `<name>.html` (and `<name>.css`) into `frontend/src/component-previews/`, then selects the new component in the Preview tab.

2. **Dev-only save endpoint**
   - New Vite plugin `frontend/vite-plugins/component-previews.js` exposes `POST /__component-previews` (dev server only, not in production builds).
   - Validates the name (lowercase letters, digits, hyphens), refuses to overwrite an existing component (409), rejects requests from other origins (403) and payloads over 1 MB.
